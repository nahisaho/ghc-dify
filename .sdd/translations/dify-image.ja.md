## Design
ダイジェストを固定した Trixie agent ベース、移設した agent venv、元の構成を保つ公式 API を使う。コピーした Next web は glibc Node/Sharp オーバーレイで動かす。PostgreSQL17.11/pgvector0.8.0、Redis8.0.2、plugin0.6.14-local、sandbox0.2.15、shellctl1.19.0、nginx/Squid/sshd/tini-supervisor は引き続き必須。/data の利用者別秘密情報と root 所有の SSH ホスト鍵を初期化する。ディレクトリは 0700、ファイルは 0600、umask077 とし、symlink は許可しない。PostgreSQL/Redis -> マイグレーション -> 補助サービス -> API/worker/beat/web -> 全役割の準備完了の順に起動し、準備期限は 300s とする。実行時の秘密情報は dev-home に置かず、dev は専用の 0700 Copilot home・作業領域だけを所有する。sshd は AllowUsers dev、PermitRootLogin no、PasswordAuthentication no、KbdInteractiveAuthentication no、AuthenticationMethods publickey、StrictModes yes を使う。登録鍵には、別の読み取り専用 authorized_keys マウントを検証して作る root 所有のコピーを使う。
ネットワーク・PID namespace は共有する。UID/DAC と chroot/seccomp によるジョブ境界を設けるが、サービス別ネットワーク分離、強制的な外向き通信制限、悪意あるプラグインの封じ込め、ポート所有権は保証しない。DB/Redis は認証必須で、プロキシは協調設定に依存する。非 root サービスは dev2000 を除く10000未満の別々の UID を使う。GID1000 はプール内のジョブ UID>=10000 専用とし、補助サービスグループや実効ケーパビリティは与えない。ジョブには秘密情報を除いた環境・マウント・FD、専用ルート、no-new-privileges を与える。root 例外は限定した初期化・sshd 監督と、信頼する sandbox broker/launcher。後者の実効権限は CHOWN,SETUID,SETGID,SYS_CHROOT だけとする。broker は root の秘密情報にアクセスできる信頼基盤の一部であり、検証済みの小さな helper とは扱わない。Node20.20.0 同梱物の所有者を sandbox 専用パスで正規化し、共有 Node24 を置き換えない。Python は root 所有でジョブから書けない信頼済み bootstrap を、事前に開いた FD・標準入力から読み込み、その後ジョブ UID に切り替える。ユーザーコード用 FD3 は保持する。preload、実行中のパッケージ導入、依存関係の変更・refresh ルートは、プロキシだけでなく broker 自体で無効にする。health と認証付きの run・読み取り専用依存関係照会だけを公開する。UID 再利用前に全ジョブプロセスを回収する。コンテナは cap-drop ALL とし、上限は CHOWN,FOWNER,SETUID,SETGID,KILL,SYS_CHROOT。子に bounding bits が残っても、ジョブの CapInh/Prm/Eff/Amb=0 と NoNewPrivs=1 で権限再取得を防ぐ。namespace 内の net.ipv4.ip_unprivileged_port_start=0 は、すべての非 root 役割に NET_BIND_SERVICE なしの80・22番への bind を許す。スパイクの UID2000 は設定0で bind80 に成功し、1024では EACCES となった。実際の nginx は未実行。SYS_ADMIN/NET_ADMIN/SYS_PTRACE/DAC_OVERRIDE/DAC_READ_SEARCH、privileged モード、host network/socket、広範なマウント、ユーザーコードの汎用特権実行は禁止する。
## 前提・リスク: 2026-11-06 14:30:34-14:39:19+09:00 の単一の時間制限付きスパイクで、chroot・権限機構の実現性ブロッカーを解消した。sandbox 全体の安全性を検証したわけではない。root 所有に正規化した実行環境と、事前に開いた標準入力を使う Python 試作は4つのケーパビリティで動いた。試作の一時的な所有者変更は、本番・並行処理の安全対策として承認されていない。broker のルート・依存関係制限、特権 bootstrap の不変性、UID のライフサイクル、Python cap/proc プローブ、最終イメージの seccomp・権限上限、独立した方針レビューは TEST-DIFYIMG-003 の必須事項として残る。権限の拡大や標準コード実行の無効化で合格させない。libmagic、venv 移設、plugin 統合、コールドスタート・停止、実際の Copilot 永続化、WSL2 は未検証。apt 情報は候補であり、TEST-DIFYIMG-001 の実ビルドで確認する。TEST-DIFYIMG-006 では FS 個別中止・所有者管理を検証し、ビルド前にピーク容量を再確認する。人間の承認は未署名。本番用成果物は存在しない。
